## 1. 系统总览：两条链路，三方合成一条训练样本

```
                    ┌─────────────────────────────────────────┐
                    │            模型文件 (.stl/.3mf)          │
                    └───────────────────┬─────────────────────┘
                    ┌───────────────────▼─────────────────────┐
                    │  几何链路（全自动，零标注）              │
                    │  解析 → 焊接 → 特征计算 → 建议映射       │
                    │  产出：几何特征向量 + 自动勾选建议        │
                    └───────────────────┬─────────────────────┘
                                        │
模型特征（自动） ────────────────────────┤
                                        ├────────► 训练样本 ──► 样本库
工况特征（人工勾选，金标准） ────────────┤            (.training-samples.json
                                        │             + bambu-data/training/files)
专家切片参数（从切片产物提取） ──────────┘                │
                                        │                ▼
                    ┌───────────────────▼─────────────────────┐   JSONL 导出
                    │  工况链路（人工标注 + 规则引擎）         │   （将来训练管线消费）
                    │  taxonomy 勾选 → 冲突校验 → 规则映射     │
                    │  产出：切片参数档 → 切片桥 → gcode       │
                    └─────────────────────────────────────────┘
                                        │
                              打印结果（成功/失败/问题）
                                        │
                                        ▼
                              outcome 奖励通道（2026-10-12 新增）
```

两个链路的**分工铁律**：
- **几何链路回答「这个件长什么样」**——纯计算，没有任何学习成分，任何模型都能算；
- **工况链路回答「这个件要怎么用」**——只有人知道，只能人工赋予（曼波 2026-10-11 纠偏定死的原则：没有人工标注的数据不构成训练集）。

## 2. 几何链路（自动链路）解读

`src/services/modelFeatures.js`，纯 Node，无 ML 依赖。

### 2.1 处理流水线

| 阶段 | 做什么 | 关键实现 |
|---|---|---|
| ① 解析 | STL（二进制/ASCII）或 3mf（`3D/Objects/*.model` XML，多零件逐件）→ 索引网格 | 顶点焊接（1e-4mm 量化）；XML vertex/triangle 正则（⚠️ 三角属性是 v1/v2/v3，别和顶点 x/y/z 混） |
| ② 逐面几何 | 面积/法线/重心 z；有号四面体体积（符号判整体朝向，翻转网格自愈） | 朝下判定 = `-nz`（外向网格朝下面法线为负，别再写反） |
| ③ 悬空分带 | 面法线与 -Z 夹角：≤25° 重悬空 / ≤50% 需关注；贴底层（z≈zmin+0.3mm）不算悬空（板托着）；上半程重悬空 = 悬端代理 | 面积加权百分比 |
| ④ 孔检测 | 拓扑亏格（genus，闭合网格精确数通道；多体相加）+ 平面片边界环内环拟圆（Kåsa 最小二乘拿孔径，上下对合口去重） | 亏格数含矩形槽等一切贯通特征；拟圆只认圆口；孔数取两者较大值 |
| ⑤ 接触面 | 贴底朝下面积 vs 包围盒占地比 | 判断「小接触面易倒」 |
| ⑥ 曲面占比 | 总面积 − 显著平面片面积（法线+平面偏移聚类） | 区分「面」与「剖分噪声」按面积门槛 |
| ⑦ 建议映射 | 特征 → taxonomy「几何体检」组 4 标签的预勾选建议（阈值单源 `THRESHOLDS`） | 只建议 true 绝不 false；阈值：悬空 8% / 曲面 30% / 接触 15% |

### 2.2 能力边界（诚实清单）

- 孔检测的 genus 把**矩形槽/镂空框也算孔**（打印同样收缩，但与"螺孔"语义不同）——Downloads 压测 42/60 触发率偏高的主因；
- 穿过曲面的孔拿得到个数（genus）拿不到半径（拟圆只走平面片）；
- 壁厚/倒扣不做（需要中轴线分析，成本不在 v1）；
- 网格不闭合时孔数降级为圆口检出并显式标注；
- **没有语义分类**：知道"有大圆柱面+4 小孔"，不知道"这叫管夹"——语义归类是将来学习模型的地盘（见 §5）。

## 3. 工况链路（人工链路）解读

`src/services/taxonomy.js`（词汇表）+ `src/services/processRules.js`（映射规则库）+ `src/services/slicerExtract.js`（参数提取）+ `scripts/slice-with-engine.js`（切片桥）。

### 3.1 主链路：勾选 → 参数 → gcode

```
人工勾选工况（taxonomy v4：9 组 24 字段，0 勾选=常规件）
   ↓ validateSelection（硬冲突 block / 软冲突 warn，材料类需传材料串）
applyRules（28 条种子规则，priority 升序叠加，大者赢）
   ↓
切片参数档（22 个白名单参数）→ 切片桥（Orca CLI）→ gcode.3mf
```

设计铁律：**每标签必须能回答映射到什么切片参数**（mapsHint 强制非空）；规则 `when` 只吃池内字段（几何数值不进 when，可审计性不被打穿）。

### 3.2 学习回路（现状：人在环的规则生长，不是 ML）

- **修正回路**：审批/使用中发现参数不合适 → 提交修正建议（自动携带勾选组合）→ 待审池聚合（同 when+set 计数）→ reviewer 采纳才转正为规则；
- **专家导入**：手工切片的 3mf → 提取参数 diff → 候选规则草稿 → 同池人工闸门；
- 这套东西的本质是「**人在环的知识库生长**」：规则由人写、由人改、由人批准——可审计性是工艺库的命根子，这是它不能被黑盒模型直接替换的原因。

## 4. 训练集（2026-10-12 起：录入工坊 + 机型隔离 + 拟合度条）

一条样本 = **三方合成 + 三个快照**（曼波定义：模型特征 + 工况特征，前者自动、后者人工）：

```jsonc
{
  "id": "T20261011-001",
  "machine": "Bambu Lab X1C",                                                        // 机型隔离（多品牌机队）
  "selection": { "fit_class": "interference", "fastener": ["machine_screw"], ... },  // 人工标注（金标准，≥1 项硬性要求）
  "spatial": [ { "tool": "bending_zone", "pos": [x,y,z], "face": 1234 }, ... ],      // 空间工况标注（3D 标注工房）
  "model":  { "features": { 几何特征全集 }, "storedPath": "bambu-data/training/files/..." },  // 自动
  "slice":  { "extraction": { "params": {...}, "diff": {...}, "estMinutes": n } },   // 从切片产物自动提取
  "fit":    { "score": 75, "matches": 3, "total": 4 },                               // 拟合度快照（见 §4.1）
  "autoSuggestion": { "through_holes": true, ... },  // 几何体检当时的自动建议（训「自动 vs 人工」一致性用）
  "outcome": { "status": "成功|失败|部分成功|未打印", "issues": "支撑翻车..." }        // 奖励信号通道（打印完回填）
}
```

- 入口：`/train.html` 训练集录入工坊（无审批——录入人即标注权威）；
- 机型隔离（2026-10-12 曼波：多品牌机队、寿命各异）：样本带 `machine` 字段按机型归档；机队档案 `.printer-fleet.json`（品牌/构建体积/可信度，人工维护）；**几何链路全机通用，工况与参数按机型隔离**；
- 存储：索引 `.training-samples.json`，文件本体归档 `bambu-data/training/files/`（项目外，push 不丢）；
- 导出：样本库页「导出 JSONL」或 `GET /api/training/export`（reviewer+），训练管线直接消费；
- ⚠️ 纪律（2026-10-11 曼波纠偏）：**没有人工工况标注的数据不是训练样本**——store 层强制勾选 ≥1 项。

### 4.1 拟合度条（2026-10-12 曼波纠正语义，替换「打印机可信度」初版）

**拟合度 = 引擎按人工工况算出的参数 ↔ 专家切片产物内嵌参数，的贴合程度**——直接度量「当前规则库对这个 case 的覆盖缺口」：

- 口径：只在**专家声明的键**上评估（专家没写 = 接受默认，不罚分）；值归一化比较（`15%≡15`、布尔、3 位小数）；
- 拟合 100% = 规则库已完整解释此切法；拟合低 = 差异项即**「可被记忆的参数」**；
- **记忆通路**：差异项一键 → 规则候选进待审池（`POST /api/print/rule-suggestions`）→ reviewer 采纳 → 规则库学会此 case。`src/services/paramFit.js` 的 `memorizable(fit)` 就是这条通路的数据形态；
- 实现链条：`computeFit()`（勾选/材料/切片任一变化即重算）→ `POST /api/training/fit` → 拟合条 + 差异表 + 记忆按钮。

### 4.2 3D 工况标注工房（2026-10-12 曼波设计：「人修正几何链路盲区」的接口）

> 「出现一个此模型渲染的 3D 窗口，底下是一排工具（工具内容是我们的工况分析：哪里受弯，哪里打印都可以在此界面完成标注）」

- `public/annotator.js`：纯 WebGL 无依赖——轨道旋转（拖拽）+ 缩放（滚轮）+ **三角面拾取**（颜色编码离屏渲染 readPixels）+ 标注点 2D 覆盖层；
- 工具排 = 空间化工况：🔴悬空需支撑 / 🟠受弯区 / 🔵受压区 / 🟣接触面 / 🟢外观面 / ⚪自由标注——点模型表面即落标注（面质心坐标）；
- 标注随样本存 `spatial` 字段——**这就是人修正几何链路的通道**：几何链路看不出的复杂特征（哪里受弯、哪里是接触面），人在 3D 视图上直接点出来，成为训练数据里的高价值空间工况特征；
- 已知限制：无头导出缩略图缺失同理（无 OpenGL）；多零件暂取首件标注；网格 >12 万面抽稀浏览。

## 5. 学习范式定位：现在是什么、不是什么、往哪走

### 5.1 直接回答

| 问题 | 答案 |
|---|---|
| 现在是强化学习吗？ | **不是。** 没有 agent、没有探索、没有奖励驱动的策略更新 |
| 现在有什么学习成分？ | ①几何链路是**确定性计算**（根本不是学习）；②工况链路是**人在环的规则知识库**（人写人改人批准）；③训练集工坊在**积累监督学习数据**（模仿学习的原料） |
| 最接近哪个范式？ | **监督学习 / 模仿学习**（"机器学人"字面义：学专家的勾选与参数决策），数据在攒、模型还没训 |

### 5.2 为什么现在不该上神经网络/强化学习（三个硬数字）

1. **标注 = 0 起步**：2026-10-11 才开出录入工坊，样本个位数；
2. **奖励贵**：RL 需要的"结果反馈"= 真实打印（小时级）+ 人工质量判定——每条奖励都是最贵的数据；
3. **探索有害**：RL 靠试错学策略，但打印的试错成本是真材料真时间，坏参数会打废板子——物理世界不是可以随便炸的模拟器。

### 5.3 演进阶梯（每级有明确触发条件，不跳级）

| 阶段 | 做什么 | 触发条件 | 状态 |
|---|---|---|---|
| L0 规则系统 | 几何特征 + 规则引擎 + 人在环修正 | — | **✅ 现役**（天生泛化：规则匹配特征不匹配具体模型，新模型直接可用） |
| L1 数据飞轮 | 录入工坊 + outcome 回填 + JSONL 导出 | — | **✅ 本轮上线** |
| L2 可学习阈值 | 小分类器（逻辑回归/GBDT）学「几何特征 → 人工是否确认该标签」 | 样本 ≥200 且某标签误报率可测（如通孔 42/60 的语义混杂） | 待数据 |
| L3 参数回归 | 标签+特征 → 参数修正量回归（学修正回路的聚合模式） | 样本 ≥500 且修正回路有稳定差值积累 | 待数据 |
| L4 形状表征 | mesh 编码（PointNet 系/多视角 CNN）→ 形状族分类 + 检索 | 带标注模型 ≥1000 | 远期 |
| L5 bandit/RL | 参数变体试验（同族件 A/B 参数，观测结果学偏好） | L2/L3 稳定 + outcome 回填率高 + 打印成本可承受试验 | 远期，届时也是 **contextual bandit 优先于完整 RL**（探索成本可控、不需要完整策略空间） |

### 5.4 一条不可协商的原则

**无论走到 L 几，规则引擎都留在最外层当可审计骨架，模型输出只能当「预填建议」。**
理由：工艺库每个参数都要能回答"为什么"（审批闸门同款原则）；黑盒模型给不出审计链，但它可以从数据里学到规则库没覆盖的关联——学到了 → 转成规则候选 → 人工审核 → 进规则库。**模型 proposes，规则 disposes。**

### 5.5 2026-10-30 更新：参数智能层已落地（v60/v61）——本文第 5.2 节的「L2 形态」成为现实

写作本文时的「往神经网络演进」路线已部分兑现，形态与当时设想有出入，以本节为准：

- **分层分工**：规则库继续承担显式工艺因果与安全硬约束（材料排除/绝缘禁 CF/耐温档），**数值工艺参数**（层高/墙/壳/填充/支撑/孔补偿/温差/裙边）由学习模型预测——「规则管因果、模型管数值、置信度管敢不敢、LOFO 竞技场管谁上岗」。
- **三族竞技**（`paramModel.js`）：kNN 案例推理（相似专家案例加权融合，天然可审计）+ 加权岭回归（工况 one-hot 进特征）+ **多层神经网络**（`mlp.js` 纯 JS 手写：多任务共享底座 24→12 双隐层、Adam、5 网络确定性集成、置换重要性）。每参数按 LOFO MAE 与中位数基线比，严格优于基线 ≥5% 才上岗——**MLP 在小样本线性数据上会诚实输给岭回归，这是机制不是缺陷**。
- **模型不改参数，只建议或修正**：shadow 模式建议只透出审批台；active 模式逐参数按置信度（≥0.55）修正，clamp 白名单域内；provenance（规则值→模型值/来源/置信度/参考案例/依据特征）随单存档。采纳、切换、下线全部 admin 手动——5.4 的原则原样生效。
- **样本权重**：打印 outcome（失败×0.3）与录入 confidence 进损失——第 4 章「outcome 是奖励信号」的设想落地。
- **已知边界**：现网 30+ 条样本的量级下 kNN/岭回归大概率上岗、MLP 待命；样本到几百条、关系非线性化后竞技场会自动换血。spec（特征全集/填补值/标准化参数）随模型 JSON 冻结，taxonomy 演进旧模型按填补值降级不崩。

## 6. 下一轮迭代方向（backlog，按优先级；✅ = 已在 v60~v62 兑现或被更好方案取代）

1. **3D 标注工房深化**：多零件逐件标注、标注区域高亮（不只点标）、框选面片、标注模板（同族件复用）；
2. **训练页实战打磨**：录入流程批量优化（一键复制上一条工况、样本编辑而非删重建）、标注数据可视化回放；
3. **STEP 支持（B-rep 真特征）**：圆角/孔位精确识别，喂给几何链路的特征精度升级；
4. **H2C 机器档接入切片桥**（Orca 2.4.2 未带：自拷 vendor 档或等官方）+ 双挤出机耗材映射；
5. **L2 触发监控**：样本库页显示「距 L2 触发还差多少」（样本数进度条），数据够了自动提醒开训；
6. ~~切片桥接进分发链~~ ✅ 已于 2026-10-18 上线（模型单审批通过 → 分发时刻自动切片排盘，`autoSlice.js`）；
7. **参数智能模型族扩展**：GBDT/更深层网络照 kNN/岭回归/MLP 同一接口插进 LOFO 竞技场（闸门保证零风险）；estMinutes/耗材预估模型（sliceStats 已采集待消费）。
