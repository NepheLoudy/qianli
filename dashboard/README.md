# 曼波大模型（qianli 本地运维台）（仅本机运行）

可视化查看 qianli 项目群全部机器人的**端口职能、权限边界、指令清单、对话监听、服务状态、
运行日志、更新状态**，并提供**本地测试进程启停**、**npm push / 安装 / stub 测试**快捷指令，
以及**定制中心**——直接在界面上读写各机器人后端的定制项（白名单/名册/管辖策略/关键词回答表）。

> 仅绑定 127.0.0.1，不部署、不对外暴露。
>
> 完整使用说明（界面口径、各机器人功能逻辑速查、持续维护工作流、巡检与 FAQ）见根目录《机器人总成使用指南.md》。

## 启动

```bash
cd dashboard
npm install
npm start        # http://127.0.0.1:3100
```

**开机自启**：Windows 登录后自动拉起（无需手动 start）。链路：启动文件夹
`%APPDATA%\...\Startup\qianli-dashboard-autostart.vbs`（隐藏窗口）→ 本目录 `autostart.bat`
→ 3100 已在监听则跳过，否则 node 后台拉起（日志写 `dashboard-run.log`，上一次运行日志留档
`dashboard-run.last.log`）。要移除自启：删启动文件夹里那个 .vbs 即可。
注意 `autostart.bat` 必须保持纯 ASCII——bat 里的 UTF-8 中文注释会被 GBK 代码页的 cmd
吞行解析成乱码命令（2026-09-13 踩过）。

**保活**：计划任务 `qianli-dashboard-keepalive` 每 10 分钟隐藏运行本目录 `keepalive.vbs`
→ 复用 `autostart.bat`（幂等：3100 已监听即退出）——进程被静默杀死后最迟 10 分钟自动复活
（2026-09-22 上线，当日实测杀进程→任务触发→HTTP 复活闭环通过；起因：当日进程曾无任何
stderr/事件日志地静默死亡）。Startup 里另有 `qianli-ops-console-autostart.vbs` 直起 node
的历史冗余路径，与保活不冲突、未清理（2026-09-22 报备）。移除保活：
`schtasks /delete /tn qianli-dashboard-keepalive /f`。

### 总览仪表台的口径说明

- **状态采样**：随运维台页面打开进行（约 25~30 秒一针，随 `/api/overview` 轮询顺带记录），
  状态未变化时原地并段省空间；历史落盘 `.status-history.json`（gitignore），保留 3 天，重启不丢；
- **状态取值**：绿=部署目标在线（pm2 online）→ 橙=仅本地测试进程在跑 → 红=离线 → 灰=未知（部署目标不可达，不计入可用率分母）；运维台自身视为恒在线；
- **可用率**：窗口内「部署目标或本地任一在跑」的时间占比；「未知」时段剔除；
- **HTTP 深度健康**：一次 SSH 批量 curl 各服务 `GET /api/health`（60s 缓存），专抓「pm2 显示 online 但接口已僵死」；
- **掉线事件**：采样史中连续「离线」时段聚合成事件（起止时刻 + 时长），仍在持续的标红；
- **队员活跃**（`/api/activity` 聚合，60s 缓存）：数据源是网关 v14 的使用统计 `GET /api/usage?days=N`
  ——消息事件命中路由后顺带计数（谁 open_id→通讯录解析姓名、什么功能：`/` 指令精确到首个 token，
  工单接单单独成桶，其余按私聊/@群对话计），按天保留 30 天，落盘部署目标机数据目录（小电脑侧 C:/home/qianli/feishu-gateway-data/；NAS 时期为
  `/home/qianli/feishu-gateway-data/`，项目外，部署清空项目目录不丢）；活跃榜展示近 24h/7天 活跃人数与消息量、Top 成员、功能使用分布；
  **活跃=正经使用口径（2026-09-22 用户拍板）**：抽奖、关键词回答等娱乐功能不计入活跃人数与成员榜
  （消费网关 `seriousActiveUsers`/`seriousUsers`，娱乐清单静态+上报自学习，见网关 README），
  「功能使用分布」仍全量展示娱乐命中；消息量 KPI 与网关日活跃表仍为交互全量口径；
- **功能激活**：聚合各域 policy 窗口（hub 回答表启停与规则数、duty 管辖群/名册/白名单、approval 审批流程与
  催办计划、网关长连接状态）；bambu（打印机登记/审批主通道/分发重试）与 ticket（播报路由/组长/审批联动/多人单窗口）已并入聚合。

## 能做什么

- **本地测试启动/停止**：一键在本机跑起任意机器人（自动 `QUIET_HOURS_DISABLED=1`，
  手动测试不受晚间静默限制）；本地实例可直接调它的 `/api/bot/test-*` 等接口做干跑。
- **快捷指令**：npm install、各项目 stub 测试、**npm run push 部署**（带提交说明输入与二次确认，
  push = 提交 → GitHub → 部署目标（小电脑）→ pm2 重启，qianli-deploy 链路）。
- **部署目标重启**（界面按钮「主机重启」）：单进程 pm2 restart + save（带确认）。
- **定制中心**：白名单加人/移人（即时生效）、触发名册通讯录同步、查看各域 policy 全景、
  编辑 hub 关键词回答表（改动写部署目标 `.local.json` 即时生效；npm push 会用本地 xlsx 版覆盖，
  持久批量编辑仍以本地 `关键词回答表.xlsx` 为准）。

## 安全与隐私

- 只读凭据：部署目标连接信息（DEPLOY_* 键）**直读 `../approval-bot/.env`**（不复制、不入库）；
- `registry.js` 只写职能与配置键名，不写真实姓名/群号/凭据；
- 本地测试进程日志只存在内存环形缓冲（600 行），不落盘、不上传。
