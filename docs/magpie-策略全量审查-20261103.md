## 域 1 · 用量调度与负载平衡

**审查发现**：
- ✅ 已有：magpie 内三池实时水位、健康分（ttft/错误率，近 24h 样本）、临期优先、水位降级线 0.2、30 分钟定时滚动。
- ⚠️ 缺口 1：降级触发是「事后」（水位跌破才停派），缺消耗速率预判 → **已补：burn-rate + ETA**（`/v1/magpie/quotas/history` 读数序列，点对下降速率中位数，过滤签到跳升）。注意：平台读数点密度为小时级，ETA 是**粗估**，仅供「抢先消耗」参考，精确账看 `magpie usage --csv`（按 session 归因）。
- ⚠️ 缺口 2：模型目录波动无人看守 → **已补：目录校验**——advice 生成时逐条对照 `/v1/models` 在线目录（本轮实战：gpt-5.4 不在目录被自动跳过，review 链落到 trae-global/deepseek-v4.1-flash-max，异源血统保住）；policy 链条目支持 `direct:true`（ZCode 直连通道跳过校验，如 deepseek/deepseek-v4-pro）。
- ⚠️ 缺口 3：负载平衡缺「在途」视角 → **已补规则**：同池在途子代理 ≤2；每批派发记账；长会话多波次之间重跑监听器。
- ⚠️ 边界（不可解，如实）：deepseek 与 bigmodel 不在 magpie 上游清单，水位本地不可查（key 在客户端账户通道）；bigmodel 为核心池 locked 本就不参与切换。

**anticipate 排序规则（最终版）**：临期积分优先 > ETA<24h 抢先消耗（重置自动回满，用掉总比作废强）> 综合分（水位×0.6 + 健康×0.4）。

## 域 2 · 工作流设计与任务分发

**审查发现**：分割与并行派发已有，但任务卡无模板、依赖拓扑只有一句话、失败路径不具体、派发无记账。

**深化部署（波次分发模型）**：
1. 任务按依赖分层成**波（wave）**：波内 Agent 单消息并行派发；波间主会话集成验收（编译/测试跑通）+ 重跑监听器刷新 advice；复杂 DAG 用 CreateWorkflow（`subagent_model` 动态传降级链模型）。
2. **任务卡七要素**（模板）：

```
[TC-<项目>-<序号>] 目标：一句话
接口契约：输入 … / 输出 … / 依赖 …（冻结后变更需上报）
验收标准（可执行判据）：测试命令 + 预期输出
文件范围：只允许触碰的路径
难度：S/M/L（hy3-grader 评）
工位：advice 定（岗位 + 链上模型）
状态：pending / in-flight / blocked / done
```

3. **失败矩阵**：失败重试 1 次 → 降级链下一档重派 → 仍失败上报主会话拆任务；攻坚岗两轮无进展必须上报。
4. **派发记账**：每批派发一条事件（工位/模型/任务数）入 events，在途负载可追溯。

## 域 3 · 子智能体头脑风暴

**审查发现**：ideate 岗位有，但视角随口定、产出无沉淀、实例数拍脑袋。

**深化部署**：
1. **标准视角集**（按任务类型选，派发时指定）：架构类=演进性/复杂度/故障面；功能类=体验/边界情况/滥用误用；算法类=正确性/复杂度/数据假设；兜底=反方（专门找茬，必须给反例）。
2. **弹性实例数**（联动 workbuddy 水位，防免费池被打爆）：水位 ≥0.6 → 3 实例；0.3~0.6 → 2 实例；<0.3 → 1 实例串行。
3. **设计决策沉淀（ADR-lite）**：ideate 收敛结论必须写进项目 CONTEXT.md——设计类事件必带收敛结论，头脑风暴不许「聊完就散」。
4. 触发时机三档：接项目方案定型前 / 开发中架构分叉点 / 验收阶段重大权衡复辩。

## 域 4 · 子智能体协助开发工作

**审查发现**：三档工位+降级链+无同文件双写已有；缺协作协议、集成验收、上下文效率设计。

**深化部署**：
1. **契约冻结协议**：分割后接口契约冻结；工位发现契约必须改 → 停手上报主会话，裁决后广播所有受影响工位（依赖单向图）。
2. **波次集成验收**：每波收尾主会话跑集成验证（编译/测试），绿了才放行下一波——拒绝「各写各的最后拼不上」。
3. **scout 前置**：开发工位派发前先派 hy3-scout 出侦察摘要附进任务卡——工位少走弯路，上下文成本大降。
4. **模型目录波动免疫**：链上模型下线自动跳档（监听器校验），目录恢复自动启用；模型变动只改 policy.json。
